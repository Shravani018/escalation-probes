# Data schema and redaction rules

Conversation files are JSONL, one record per line. `scripts/validate_data.py` and `validate_conversations` in `src/escalation_probes/data.py` enforce the fields below.

## Conversation fields

| Field | Type | Meaning |
|---|---|---|
| `id` | string | unique record id |
| `label` | `escalation` or `benign_control` | conversation type |
| `category` | `phishing_fraud` or `cyber_intrusion` | study category |
| `objective` | string | the goal asked directly, used by the Attack Objective condition |
| `turns` | list of `{user, assistant}` | alternating user and assistant text; the last entry's `assistant` is the final reply |
| `matched_to` | string | controls only: id of the escalation conversation it matches |

A control has the same category and turn count as its escalation conversation, and its per-turn word count stays within 20%. In round two a control also shares turns 1 and 2 with its partner and then moves to a defensive or awareness request on the same topic.

## Other files

| File | Content |
|---|---|
| `data/prompts_v2/*.jsonl` | round-two user-turn sets from `scripts/build_prompts.py`, without replies |
| `data/multi_turn_gen_<model>/`, `data/controls_gen_<model>/` | the same conversations with each model's own greedy replies from `scripts/generate_replies.py` |
| `data/output_labels_<model>.csv` | columns `id`, `label`; `label` is `refused`, `partial` or `complied`, set by hand with `scripts/label_outputs.py` |
| `data/single_turn_reference/*.jsonl` | 100 benign and 100 harmful single-turn records, with `response` as the text the probe reads |
| `results/judge/judge_hf_<model>.jsonl` | one row per turn: `record_id`, `label`, `turn`, `status`, `flag`, `score`, `rationale`, `judge_model`, `prompt_sha256` |

## Redaction

Replace the following before any prompt is run. `scripts/prepare_reference_data.py` applies the same rules to the single-turn records.

| Item | Placeholder |
|---|---|
| links and domains | `[LINK]` |
| credentials, tokens, account numbers, email addresses | `[CREDENTIAL]` |
| named people, organizations, systems, IP addresses | `[TARGET]` |
| commands, code, exploit detail | `[REDACTED]` |

The target paper's phishing criteria require a specific link. Here the link stays a placeholder, so success is judged on structure and intent, not on a working artifact.

## Sourcing

1. Single-turn benign and harmful records are sampled deterministically from the retain and circuit-breaker sets that the target paper uses.
2. Multi-turn user turns are self-authored templated arcs built by `scripts/build_prompts.py`. They are not adaptive and use no operational detail.
3. Replies are generated by each model, then labelled by hand. Generated replies, labels and judge outputs may contain unsafe text and are kept out of Git.

## Checks

`validate_data.py` checks required fields, category and label values, non-empty `turns` with `user` and `assistant` text, the redaction patterns (links, emails, IP addresses, code fences), control matching and the 20% per-turn length rule. Run it before every caching job. `tests/test_no_leakage.py` checks that no test conversation reaches PCA fitting, probe training or layer selection.
